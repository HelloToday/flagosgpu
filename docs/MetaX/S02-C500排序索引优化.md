# S02：C500 排序索引优化

## 1. 机制、环境与边界

S01 的 E2 保留 8 轮 4-bit radix sort 及其全局直方图、lookback 和稳定 scatter 协议。本阶段只将前 7 轮的索引 payload 从 int64 改为 int32，末轮直接扩宽写入 int64 公开输出；两个 int32 中间缓冲加一个 int64 最终缓冲为每元素 16 B，收益来自各 pass 搬运宽度。selector 仅选中 MetaX FP32、4-bit radix、`2048 <= n < 2**30` 且 `numel <= 2**31-1`，其他输入仍走 int64 路径。

预验证平台为 1×MetaX C500 64 GB，驱动 3.8.30、MACA 3.7.0.38、Python 3.12.11、`torch 2.8.0+metax3.7.0.7`、`triton 3.0.0+metax3.7.0.7`。plugin 为 `47882ba2585dafdec92f06aff8ceb8af1de54630`，当前复现固定为 `FlagGems@1bbd3c585de61b9c7850dead56fb3b01ee81a546`；实验时本地为 `FlagGems@a7706f680ccc5b6e6fc6f3cb14a1987b98ce420b` 加未提交本改动，租赁机 HEAD 为 `36e2f7fc641d2e0cd6f5823181a5b7ee11cebd96` 且工作树含 E2 与同一改动。实际导入来自 `/data/flagos/src/FlagGems/src/flag_gems` 和 `/data/flagos/src/vllm-plugin-FL`，vLLM 来自镜像 site-packages；本结果是租赁 C500 预验证。

## 2. 实现与回归源码

以下实现来自 `FlagGems/src/flag_gems/ops/sort.py`，按实际连续区间收录。

```python
def _select_sweep_use_int32_indices(dtype, k_bits, n, numel):
    return (
        runtime_device.vendor_name == "metax"
        and dtype == torch.float32
        and k_bits == 4
        and 2048 <= n < (1 << 30)
        and numel <= (1 << 31) - 1
    )


```

selector 接收 dtype、每轮 radix 位宽、行长 `n` 和总元素数 `numel`，只为 MetaX FP32/k4 且 `2048<=n<2**30` 的输入选择 int32 索引搬运。索引 payload 表示每行的原位置 `0..n-1`，这些非负整数在范围内可无损存入 int32，不涉及 FP32 键的截断或量化。`numel<=2**31-1` 是启用范围的保守限制，超出即保留原 int64 路径。中间索引的存储宽度与 tensor 地址宽度分别处理，后面的 `pid_m*N` 等跨行偏移仍用 int64 形成。这样只缩短每轮关联索引的读写数据量，公开返回的 int64 索引和稳定排序语义由末轮输出继续保证。

```python
@triton.jit
def sweep(
    arr_ptr,
    associate_arr_ptr,  # inputs: (key & value)
    out_ptr,
    associate_out_ptr,  # outputs: (key & value)
    excumsum_bins_ptr,
    global_hist_ptr,
    status_ptr,  # aux input and status
    n_passes,
    pass_id,
    bit_offset,
    m,
    N,
    OUT_N,
    TILE_N: tl.constexpr,
    TILE_R: tl.constexpr,
    k_bits: tl.constexpr,
    descending: tl.constexpr,
    SKIP_EMPTY_BINS: tl.constexpr = False,
    SKIP_GLOBAL_EMPTY_BINS: tl.constexpr = False,
    USE_INT32_INDICES: tl.constexpr = False,
):
```

`USE_INT32_INDICES` 是新的 constexpr 开关，让启用路径和 fallback 分别编译出对应地址处理，避免在设备每个元素上判断索引类型。键、附带索引、全局直方图、桶起点和 status 仍使用原参数位置，索引实际加载宽度由传入指针的 dtype 决定。E2 的局部与全局空桶开关独立保留，int32 路径仍必须执行它们既有的同步和稳定 scatter 协议。前几轮可以传 int32 输入/输出指针，末轮则传 int32 输入和 int64 输出指针，因此同一 sweep 接口承担最终扩宽。开关默认 false，使未选中的 dtype、厂商或形状继续沿用原 int64 数据流。

```python
    # load data
    pid = tl.program_id(0)
    pid_m = pid % m
    pid_n = pid // m
    pid_r = tl.program_id(1)
    pid_m_offset = pid_m
    if USE_INT32_INDICES:
        pid_m_offset = pid_m.to(tl.int64)
    row_offset = pid_m_offset * N
```

`pid_m` 选择行，`pid_n` 选择该行 tile，`pid_r` 选择桶组，这组网格映射沿用 E2。int32 payload 路径把用于地址运算的 `pid_m_offset` 转成 int64，再计算 `row_offset=pid_m_offset*N`。比如后面一行的起点远大于本行索引值时，地址仍需要覆盖整张 tensor，而关联索引只保存行内原位置。这个宽偏移会同时用于键、索引和输出，保证它们访问同一行且不会因索引缓冲缩窄而改变地址计算。缩小的是搬运的索引元素，地址安全由宽行偏移和后续 tail mask 共同维持。

```python
    # cumsum for a bin_index
    n_offsets = pid_n * TILE_N + tl.arange(0, TILE_N)  # (TILE_N, )
    mask = n_offsets < N
    arr = tl.load(arr_ptr + row_offset + n_offsets, mask=mask)
    arr_u = convert_to_uint_preverse_order(arr, descending)
    key = (arr_u >> bit_offset) & bfe_mask  # (TILE_N, )
    if associate_arr_ptr is not None:
        associate_arr = tl.load(associate_arr_ptr + row_offset + n_offsets, mask=mask)
    # since triton can only use scalar as condition, loop by bin_index
    # status must be pre zero-initialized, or else we have to initialize it
    for bin_index in range(cta_r_start, cta_r_end):
        hist_offset = pid_m_offset * (n_passes * r) + pass_id * r + bin_index
        process_bin = True
        if SKIP_GLOBAL_EMPTY_BINS:
            global_sum = tl.load(global_hist_ptr + hist_offset)
            process_bin = global_sum != 0
        if process_bin:
            matches = tl.where(mask, key == bin_index, False)  # (TILE_N, ) bool
            # cta level cumsum per bin
            # CAUTION: tl.sum in triton 3.2 does not promote type
            local_sum = tl.sum(matches.to(tl.uint32), axis=0)
            pack0 = aggregate_mask | local_sum
            status_offset = (
                pid_m_offset * (r * OUT_N) + bin_index * OUT_N + pid_n
            )
            tl.store(status_ptr + status_offset, pack0, cache_modifier=".cg")
```

键和关联索引按相同的 `row_offset+n_offsets` 读取，mask 只允许当前行的合法位置参加本轮排序。FP32 键经原保序转换提取当前 digit，payload 缩为 int32 不参与 digit 分类。直方图与 status 的跨行偏移使用同一 int64 行号，防止大批量时不同元数据区域发生错位。行全局桶计数为零时，所有 CTA 一致跳过；全局非空时，即使本 CTA 无命中也先发布带 aggregate 标签的零局部计数。这个区别保证后续 CTA 的 lookback 可看到就绪状态，缩窄索引搬运不会破坏 E2 的跨 CTA 协议。

```python
            # decoupled lookback
            exclusive_prefix = tl.zeros((), dtype=tl.uint32)
            i_lookback = pid_n - 1
            while i_lookback >= 0:
                flag_offset_i = (
                    pid_m_offset * (r * OUT_N) + bin_index * OUT_N + i_lookback
                )
                pack1 = tl.load(status_ptr + flag_offset_i, volatile=True)  # uin32
                while pack1 == 0:
                    pack1 = tl.load(status_ptr + flag_offset_i, volatile=True)
                exclusive_prefix += pack1 & v_mask
                if (pack1 & aggregate_mask) == aggregate_mask:
                    i_lookback -= 1
                else:
                    i_lookback = -1
            pack2 = inclusive_prefix_mask | (exclusive_prefix + local_sum)
            tl.store(status_ptr + status_offset, pack2, cache_modifier=".cg")
```

lookback 从当前 tile 的前一个 CTA 开始，读取同一行同一桶的 packed status，零值表示尚未就绪，需要继续等待。遇到 aggregate 就累加低位计数并向前走，遇到 inclusive 就取得已有完整前缀并结束，随后发布当前 CTA 的 inclusive 总数。`flag_offset_i` 使用 int64 行偏移，改变的是元数据寻址的安全宽度，计数标签和 uint32 累加仍沿原协议。局部零计数的 CTA 也必须参与该状态链，因为后面的非空 CTA 可能依赖它的就绪信息。最终 `exclusive_prefix` 表示所有前置 tile 的同桶元素数，下一段用它确定稳定输出位置。

```python
            if not SKIP_EMPTY_BINS or local_sum != 0:
                local_ex_cumsum = (
                    tl.cumsum(matches.to(tl.uint32), axis=0) - matches
                )  # (TILE_N, )
                ex_cumsum_in_bin = (
                    exclusive_prefix + local_ex_cumsum
                )  # global ex_cumsum_in_bin (TILE_N, )

                # ex_cumsum_bins (m, n_passes, r)
                ex_cumsum_bins = tl.load(excumsum_bins_ptr + hist_offset)  # scalar
                pos = ex_cumsum_bins + ex_cumsum_in_bin  # (TILE_N, )

                # scatter
                tl.store(out_ptr + row_offset + pos, arr, mask=matches)
                if associate_arr_ptr is not None:
                    tl.store(
                        associate_out_ptr + row_offset + pos,
                        associate_arr,
                        mask=matches,
                    )
```

`local_ex_cumsum` 按 lane 顺序计算本 tile 内的同桶排他前缀，再与前置 CTA 前缀和全局桶起点相加得到 `pos`。值与原位置索引用相同 mask 和 `row_offset+pos` 写出，所以相等键继续保留输入顺序，输出索引仍能还原对应键。局部空桶在完成全局状态协议后可跳过这一段，节省局部 scan 和 scatter。前 7 轮的输出索引指针为 int32，最后一轮指向 int64 缓冲，store 时直接将非负 int32 payload 精确扩宽。末轮本来就要散写全部合法索引，把扩宽放在同一次 store 可避免另发一整个索引转换 kernel。尾部无效 lane 不匹配任何桶，不会写入键或最终索引。

```python
        # sort
        arr_in = torch.clone(arr)
        use_int32_indices = _select_sweep_use_int32_indices(
            dtype, k_bits, n, arr.numel()
        )
        index_dtype = torch.int32 if use_int32_indices else torch.int64
        indices_in = (
            torch.arange(0, n, dtype=index_dtype, device=arr_in.device)

            .contiguous()

        indices_out = torch.empty_like(indices_in)

        )
```

键先 clone 到独立输入缓冲，保护调用方原 tensor，索引则根据 selector 选用 int32 或 int64 的 `arange(0,n)`。`broadcast_to(...).contiguous()` 为每行建立完整原位置数组，另一个同 dtype 的 `indices_out` 用于中间 pass 的 ping-pong。启用时额外准备 int64 `final_indices`，只让末轮写入并作为公开结果返回，前几轮仍以 int32 搬运。两个 int32 中间缓冲加一个 int64 最终缓冲合计每元素 16 B，与两组 int64 缓冲的总字节数相同，收益依据是各 pass 的访存宽度。fallback 继续建立两组 int64 索引且 `final_indices=None`，不会为未选中的路径引入额外最终缓冲。

每轮先清零 status，再按 `bit_offset=i*k_bits` 对当前 digit 做稳定 sweep，原 E2 的直方图与空桶协议继续使用。FP32/k4 有 8 轮，前 7 轮把 `associate_out` 指向 int32 中间缓冲，末轮改指 int64 `final_indices`。键缓冲每轮都交换，索引缓冲在中间轮也交换，最后一轮则把返回引用直接设为最终 int64 tensor。这样的引用安排保证末轮扩大后的数据不会再作为 int32 指针读取，也不会需要事后复制或转换。三个 selector 各自传入 sweep，索引宽度、局部空桶和全局空桶的职责保持独立。未选中 int32 时所有轮仍交换原 int64 输入/输出缓冲，返回行为与原路径一致。

```python
def _metax_radix_sort_candidate_and_original(y, descending):
    sort_module = importlib.import_module("flag_gems.ops.sort")
    original_hist_selector = sort_module._select_global_hist_kernel
    original_sweep_selector = sort_module._select_sweep_skip_empty_bins
    original_global_sweep_selector = (
        sort_module._select_sweep_skip_global_empty_bins
    )
    original_index_selector = sort_module._select_sweep_use_int32_indices
    with flag_gems.use_gems():
        candidate = sort_module.radix_sort(y, k_bits=4, descending=descending)
        sort_module._select_global_hist_kernel = (
            lambda dtype, k_bits, n: sort_module.compute_global_hist_kernel
        )
        sort_module._select_sweep_skip_empty_bins = lambda dtype, k_bits, n: False
        sort_module._select_sweep_skip_global_empty_bins = (
            lambda dtype, k_bits, n: False
        )
        sort_module._select_sweep_use_int32_indices = (
            lambda dtype, k_bits, n, numel: False
        )
        try:
            original = sort_module.radix_sort(y, k_bits=4, descending=descending)
        finally:
            sort_module._select_global_hist_kernel = original_hist_selector
            sort_module._select_sweep_skip_empty_bins = original_sweep_selector
            sort_module._select_sweep_skip_global_empty_bins = (
                original_global_sweep_selector
            )
            sort_module._select_sweep_use_int32_indices = original_index_selector
    return candidate, original


```

这个 helper 保存当前直方图、两种空桶和 int32 索引四个 selector，然后先对同一输入运行完整候选。构造通用对照时同时关闭四项专用选择，确保回归检查的是整个优化组合与原通用协议，而不是只关闭其中一项。`finally` 恢复全部模块属性，即使对照调用失败也不会让后续 case 继承关闭状态。返回的两组值和索引用于位级差分，排序方向和输入保持相同，有助于发现组合间的交互错误。selector 替换只发生在独立测试 helper 中，不修改生产 selector 或官方 benchmark 的运行行为。

这个 helper 先运行包含 int32 的候选，再只把 int32 selector 临时关闭，直方图和 E2 两级空桶快路继续使用原设置。两次 radix 调用采用相同输入与方向，因此差异专门对应索引搬运宽度和末轮扩宽这一项。对照仍保留 E2，可以用来发现 int32 关联索引错位、地址溢出或最终返回 dtype 的错误。`finally` 无条件恢复 selector，让其他 case 继续测试正常候选，而不会产生依赖执行顺序的结果。函数只返回待比较的键与索引，本身不测吞吐，也不改变官方 workload。

```python
def test_sort_metax_fp32_radix_int32_indices(
    batch_size, hiddensize, descending
):
    """Preserve stable int64 indices and all FP32 key bit patterns."""
    positions = torch.arange(hiddensize, dtype=torch.int32).unsqueeze(0)
    rows = torch.arange(batch_size, dtype=torch.int32).unsqueeze(1)
    input_bits = (
        0x3F000001 + ((rows % 8) << 20) + ((positions // 2048) % 2) * 13
    ).to(torch.int32)
    special_bits = torch.tensor(
        [0, -2147483648, 2139095040, -8388608, 2143289345, -4194303],
        dtype=torch.int32,
    )
    input_bits[:, : special_bits.numel()] = special_bits
    input_bits_before = input_bits.clone()
    y = input_bits.view(torch.float32).to(flag_gems.device)
    y_bits_before = y.view(torch.int32).clone()
```
