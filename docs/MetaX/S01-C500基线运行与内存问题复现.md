## 2. 代码修改与关键不变量

### 2.1 M1：把逐层 Prefill 同步提升到 metadata builder

M1 把 42 层重复的 `prefill_seq_lens` 设备到主机同步与累计和提升到 metadata builder，每调度步计算一次并由所有层共享。它仅在 Prefill、非 cascade 且 DCP world size 为 1 时预计算，其他路径使用 `None` fallback。源码位于 `vllm-plugin-FL/vllm_fl/dispatch/backends/vendor/metax/impl/attention/flash_attn.py@47882ba2585dafdec92f06aff8ceb8af1de54630`。

```python
causal: bool = True
prefill_cu_seq_lens: torch.Tensor | None = None
```

这个字段为当前调度步的 Prefill 累计 K 长度保存一个可选 GPU tensor 引用，metadata 本身负责把引用传给各 Attention 层。42 层看到的是同一份边界，因此无需各自从设备取回长度再重新构造 tensor。默认值 `None` 表示 builder 没有为本路径预计算，调用点仍能进入原有 fallback。`causal` 字段继续独立保留，新增累计边界不会改变查询可见性或 Attention 的数值规则。共享范围限于一次调度步，下一步根据新的序列状态重新生成 metadata，不能把这份 tensor 当作跨步缓存。

```python
prefill_cu_seq_lens = None
if num_prefills > 0 and not use_cascade and self.dcp_world_size == 1:
    prefill_cu_seq_lens = torch.cat(
        (prefill_seq_lens.new_zeros(1), prefill_seq_lens)
    ).cumsum(dim=0, dtype=torch.int32)
```

builder 在存在 Prefill、未使用 cascade 且 DCP world size 为 1 时预计算累计长度，这些条件对应本次可安全共享的调用范围。`new_zeros(1)` 继承 `prefill_seq_lens` 的设备和初始 dtype，再与实际长度拼接，累计和明确输出 int32。比如长度 `[3, 2]` 变成边界 `[0, 3, 5]`，相邻边界之差仍为各序列的 K 长度。计算留在设备上，避免逐层 `.tolist()` 所需的设备到主机同步，并把重复累计和缩到每调度步一次。不满足条件时变量仍为 `None`，调用点负责按原语义生成边界，DCP 或 cascade 的其他元数据不被这个短路径代替。

### 2.2 MetaX FP32 4-bit radix 直方图

直方图修改用 MetaX `tl.histogram` 取代逐桶比较全部元素的实现。输入是每轮 radix pass 的 FP32 键，输出是 16 个桶的全局计数；尾部无效 lane 进入额外桶且不写回。selector 在 MetaX、FP32、4-bit 且 `n>=1024` 时启用。

```python
from flag_gems.ops.topk import _get_finfo_val, _get_iinfo_val, argsort

from flag_gems.runtime import torch_device_fn
from flag_gems.utils import libentry

logger = logging.getLogger(__name__)
GLOBAL_HISTOGRAM_MIN_N = 1024
```

`runtime_device` 提供 selector 所需的实际厂商身份，让 MetaX 专用 kernel 能沿现有 sort 分派入口选择。`torch_device_fn` 提供张量设备上下文，分配和 launch 仍跟随输入所在设备。来自 top-k 的数值边界和 argsort helper 继续供原 sort 文件使用，`libentry` 也保留既有入口依赖。`GLOBAL_HISTOGRAM_MIN_N=1024` 给直方图专用路径设置行长门槛，后面 selector 同时检查 FP32 和 4-bit。这里只建立依赖与阈值，不执行排序，也不改变其他 dtype 或厂商的默认选择。

```python
@triton.jit
def compute_global_hist_kernel_metax_fp32_k4(
    arr_ptr,
    out_ptr,
    num_passes,
    m,
    n,
    tiles_n_per_cta,
    TILE_N: tl.constexpr,
    TILE_R: tl.constexpr,
    num_bits_per_pass: tl.constexpr,
    descending: tl.constexpr,
):
    """MetaX FP32/k_bits=4 histogram without a bin-by-element matrix."""
    tl.static_assert(num_bits_per_pass == 4)
    pid = tl.program_id(0)
    pid_n = pid // m
    pid_m = pid % m

    r: tl.constexpr = 16
    histogram_bins: tl.constexpr = 32
    bfe_mask: tl.constexpr = r - 1
    CTA_TILE_N: tl.constexpr = TILE_N * tiles_n_per_cta
    cta_n_start = CTA_TILE_N * pid_n
    cta_n_end = tl.minimum(cta_n_start + CTA_TILE_N, n)
    bin_indices = tl.arange(0, histogram_bins)
```

每个 CTA 是一组合作执行的设备线程，`pid_m` 选择行，`pid_n` 选择该行的连续分片，因此不同 CTA 的输入范围互不重叠。`CTA_TILE_N=TILE_N*tiles_n_per_cta` 确定分片跨度，`cta_n_end=min(start+span,n)` 保留最后分片的真实边界。4-bit digit 只有 0 到 15 共 16 个真实桶，kernel 准备 32 个 histogram 槽位，以便另用编号 16 容纳无效 lane。`bin_indices` 同时索引这些槽位，后面的写回 mask 只允许前 16 个真实桶进入全局结果。这样可用 CTA 内 histogram 代替桶与元素的比较矩阵，而 padding 仍有独立去处，不能被误计为 digit 0。

```python

    for p in range(0, num_passes):
        bit_offset = p * num_bits_per_pass
        acc = tl.zeros((histogram_bins,), dtype=tl.int32)
        for n_start in range(cta_n_start, cta_n_end, TILE_N):
            n_offsets = n_start + tl.arange(0, TILE_N)
            mask = n_offsets < cta_n_end
            arr = tl.load(arr_ptr + pid_m * n + n_offsets, mask=mask, other=0.0)
            arr = convert_to_uint_preverse_order(arr, descending)
            key = ((arr >> bit_offset) & bfe_mask).to(tl.int32)
            # Padding lanes use bin 16; only the 16 radix bins are written.
            key = tl.where(mask, key, r)
            acc += tl.histogram(key, histogram_bins).to(tl.int32)
        tl.atomic_add(
            out_ptr + pid_m * num_passes * r + p * r + bin_indices,
            acc,
            mask=bin_indices < r,
            sem="relaxed",
        )


def _select_global_hist_kernel(dtype, k_bits, n):
    if (
        runtime_device.vendor_name == "metax"
        and dtype == torch.float32
        and k_bits == 4
        and n >= GLOBAL_HISTOGRAM_MIN_N
    ):
        return compute_global_hist_kernel_metax_fp32_k4
    return compute_global_hist_kernel
```

每个 pass 从保序无符号键中提取当前 4-bit digit，升降序变换仍由 `convert_to_uint_preverse_order` 负责，不对 FP32 原始值做舍入。分片内逐 tile 读取后，越界 lane 的 digit 被改成 16，再通过 `tl.histogram` 累加 32 槽位计数。比如最后一个 tile 只有 3 个合法值，其余 lane 全进入 padding 桶，真实 16 桶的总计数仍恰好为 3。CTA 的局部计数用 atomic add 合并到 `[row, pass, bin]` 的全局直方图，输入直方图先置零以保证多 CTA 累加正确。selector 只在 MetaX FP32/k4 且行长达到 1024 时返回专用实现，其他条件保留通用 kernel。被减少的是逐桶反复比较元素的统计工作，计数输出布局和后续前缀语义保持一致。

### 2.3 sweep 全局空桶快路 E2

E2 复用 `global_hist[m, pass, bin]`：行内某 pass 的全局计数为 0 时，所有 CTA 一致跳过状态发布、lookback、局部前缀和与散写；全局非空桶继续使用原局部空桶快路。selector=false 时 constexpr 分支不读取新字段。selector 在 MetaX、FP32、4-bit 且 `n>=2048` 时启用，固定源码版本为 `FlagGems@a7706f680ccc5b6e6fc6f3cb14a1987b98ce420b`。


两个 selector 分别控制局部空桶和行全局空桶快路，虽然采用同样的 MetaX/FP32/k4/2048 门槛，判断范围和能跳过的工作不同。`sweep` 的输入包含排序键、原位置索引、桶起点、全局计数和跨 CTA 的 status，输出键与同步重排的索引。`SKIP_GLOBAL_EMPTY_BINS` 允许整行某桶为空时跳过全局协议，`SKIP_EMPTY_BINS` 仅允许本 CTA 无命中时省去局部前缀与散写。两者是 constexpr，selector 未启用时相关专用分支在编译中消去，其他输入继续走原流程。下面按固定 E2 版本解释协议，当前 int32 payload 开关和末轮输出接入另见 [S02](S02-C500排序索引优化.md)。

每个 CTA 先用 `pid_m*N+n_offsets` 读取本行 tile 的键和伴随索引，`mask` 排除末 tile 的越界位置。进入桶循环后，`hist_offset` 指向当前行、pass 和桶的全局计数，这个地址与本 CTA 的局部命中情况无关。E2 读取的 `global_sum==0` 表示该行所有 CTA 都没有这个 digit，因此所有参与者一致得到 `process_bin=False`。只有这种行全局空桶才能一起跳过状态发布、lookback、局部前缀与散写，省掉整桶的同步和计算。若全局计数非零，即使本 CTA 的 `local_sum` 稍后为零也必须继续执行协议，避免其他 CTA 等待永不发布的状态。

```python
            tl.store(status_ptr + status_offset, pack2, cache_modifier=".cg")
```

`matches` 只标记合法且命中当前桶的 lane，先转 uint32 再求和，避免依赖 Triton 求和自动提升布尔类型。CTA 将 `aggregate_mask|local_sum` 写入自己的 status，值为零的局部桶也带有非零标签，因此后续 CTA 能区分已就绪零计数和未就绪状态。lookback 从前一个 tile 向前读取，遇到零 status 就等待，遇到 aggregate 就累加载荷并继续，遇到 inclusive 则取得完整前缀后结束。随后发布 `inclusive_prefix_mask|(exclusive_prefix+local_sum)`，让更后的 CTA 可以少走几步。局部空桶仍完成这些状态转换，才能保证行全局非空桶不会死等或漏计前缀。E2 的省略只发生在上一段证明所有 CTA 一致跳过的全局空桶中。

```python

            if not SKIP_EMPTY_BINS or local_sum != 0:
                local_ex_cumsum = (
                    tl.cumsum(matches.to(tl.uint32), axis=0) - matches
                )  # (TILE_N, )
                ex_cumsum_in_bin = (
                    exclusive_prefix + local_ex_cumsum
                )  # global ex_cumsum_in_bin (TILE_N, )

                # ex_cumsum_bins (m, n_passes, r)
                ex_cumsum_bins = tl.load(excumsum_bins_ptr + hist_offset)  # scalar
                pos = ex_cumsum_bins + ex_cumsum_in_bin  # (TILE_N, )

                # scatter
                tl.store(out_ptr + pid_m * N + pos, arr, mask=matches)
                if associate_arr_ptr is not None:
                    tl.store(
                        associate_out_ptr + pid_m * N + pos,
                        associate_arr,
                        mask=matches,
                    )
```

通过全局协议后，只有 `local_sum!=0` 或局部快路关闭时才计算 tile 内 cumsum，从而省去无命中 CTA 的局部扫描。命中元素的位置由全局桶起点、前置 CTA 的 exclusive prefix 和本 tile 内 exclusive prefix 相加，三部分分别决定桶区间、tile 区间和 lane 顺序。比如同桶元素出现在两个相邻 tile 中，前一个 tile 的总数会成为后一个 tile 的偏移，因此相等键继续按原顺序排列。键与伴随索引使用完全相同的 `pos` 和 `matches` 写出，保持值与原位置的一一对应。此处固定 E2 片段的索引 payload 沿用 int64，当前组合在 [S02](S02-C500排序索引优化.md) 保留同一位置协议并改变中间搬运宽度。尾部无效 lane 不参与 matches，也就不会写入输出。

```python
def radix_sort(arr, k_bits=8, descending=False):
    n = arr.shape[-1]
    m = arr.numel() // n
    assert n < (1 << 30), "we have not implemented 2**30 per launch"
    dtype = arr.dtype
    num_bits = 1 if dtype == torch.bool else (arr.itemsize * 8)

    TILE_N = 1024
    tiles_n_per_cta = 8
    CTA_TILE_N = tiles_n_per_cta * TILE_N

    num_bins = 2**k_bits
    n_passes = triton.cdiv(num_bits, k_bits)
    TILE_R = 16

    grid_n = triton.cdiv(n, CTA_TILE_N)
    grid_for_global_hist = (m * grid_n, 1, 1)

    with torch_device_fn.device(arr.device):
        global_hist = torch.zeros(
            (m, n_passes, num_bins), device=arr.device, dtype=torch.int32
        )
        global_hist_kernel = _select_global_hist_kernel(dtype, k_bits, n)
        global_hist_kernel[grid_for_global_hist](
            arr,
            global_hist,
            n_passes,
            m,
            n,
            tiles_n_per_cta,
            TILE_N,
            TILE_R,
            k_bits,
            descending,
        )
        ex_cumsum_bins = torch.cumsum(global_hist, -1) - global_hist
        ex_cumsum_bins = ex_cumsum_bins.to(torch.uint32)
```

`n` 是每行的末维长度，其他维展平为 `m` 行，单次 launch 的行长必须小于 `2**30` 以满足 status 计数载荷范围。FP32 的 32 个键位在 k4 下分成 8 个 pass，每个 pass 的 16 桶全局计数保存为 `[m,n_passes,num_bins]`。直方图先分配为零，再用 selector 选择通用或 MetaX 专用统计 kernel，每个 CTA 的 atomic add 才能得到正确总计数。`cumsum(global_hist)-global_hist` 生成排他桶前缀，例如桶计数 `[2,0,3]` 对应起点 `[0,2,2]`。这些 uint32 起点给 sweep 定义每桶的输出区间，既避免重复计算，也与现有计数和稳定散写协议兼容。

```python
def _metax_radix_sort_candidate_and_original(y, descending):
    sort_module = importlib.import_module("flag_gems.ops.sort")
    original_hist_selector = sort_module._select_global_hist_kernel
    original_sweep_selector = sort_module._select_sweep_skip_empty_bins
    original_global_sweep_selector = (
        sort_module._select_sweep_skip_global_empty_bins

    with flag_gems.use_gems():
        candidate = sort_module.radix_sort(y, k_bits=4, descending=descending)
        sort_module._select_global_hist_kernel = (
            lambda dtype, k_bits, n: sort_module.compute_global_hist_kernel
        )
        sort_module._select_sweep_skip_empty_bins = lambda dtype, k_bits, n: False
        sort_module._select_sweep_skip_global_empty_bins = (
            lambda dtype, k_bits, n: False
        )
        try:
            original = sort_module.radix_sort(y, k_bits=4, descending=descending)
        finally:
            sort_module._select_global_hist_kernel = original_hist_selector
            sort_module._select_sweep_skip_empty_bins = original_sweep_selector
            sort_module._select_sweep_skip_global_empty_bins = (
                original_global_sweep_selector
            )
    return candidate, original
```

```python
def test_sort_metax_fp32_radix_global_empty_bins(
    batch_size, hiddensize, descending, distribution
):
    """Skip only row-global empty bins and preserve stable ordering."""
    positions = torch.arange(hiddensize, dtype=torch.int32).unsqueeze(0)
    rows = torch.arange(batch_size, dtype=torch.int32).unsqueeze(1)
    if distribution == "equal":
        input_bits = torch.full(
            (batch_size, hiddensize), 0x3F800001, dtype=torch.int32
        )
    elif distribution == "local_empty":
        input_bits = torch.where(
            positions < 2048,
            torch.tensor(0x3F800001, dtype=torch.int32),
            torch.tensor(0x3F80000E, dtype=torch.int32),
        ).expand(batch_size, hiddensize).clone()
    else:
        input_bits = (
            0x3F000001
            + ((rows % 8) << 20)
            + ((positions // 2048) % 2) * 13
        ).to(torch.int32)
```

`equal` 把整行填成同一编码，令每个 pass 中除一个 digit 外的桶都全局为空，可检查 E2 是否一致跳过这些桶。`local_empty` 让前 2048 个位置和其余位置采用不同编码，从而让某些 CTA 局部无命中但行全局计数仍大于零。此时必须发布零局部状态并参与 lookback，若把局部空误当全局空，后续 CTA 可能等待或得到错误偏移。`cross_row` 根据行号和 tile 号改变 digit 分布，检查直方图与 status 的行偏移没有互相串用。batch、阈值、full/tail tile 与升降序参数一起覆盖空桶快路的实际形状边界，输入由确定性位模式构造，便于精确重现。
