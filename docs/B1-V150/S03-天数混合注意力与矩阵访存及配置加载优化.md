# S03：天数混合注意力、矩阵访存与配置加载优化

本阶段把实际模型中的三类工作分别放到合适路径：Mixed batch 中单查询序列复用原分页 Decode，多查询序列保留 Q16 Prefill；宽输出 BF16 GEMM 在既有配置内重排 program ID；默认内部 SQLite 只反射本次需要的配置表。Attention 的浮点数学、模型参数、服务配置、调优配置和缓存 key 均保持原语义。Prefill 的完整源码只在 [S01](S01-天数分页GQA注意力优化.md)，Decode 的完整源码只在 [S02](S02-天数纯Decode直接序列索引与分页归约优化.md)，唯一 A0/B1 正式四行表、精度与统计说明维护于[本文第 6 节](#6-精度与官方正式结果)。

## 1. 实际热点与实现边界

MiniCPM5-2B使用BF16、42层、16个Q头与2个KV头、head dim128。当前组合改后实际模型4K初始短窗中，GEMM占可验证device kernel时长总和56.46%，Prefill占32.57%；heavy-Mixed窗对应54.08%/31.78%，其中q1 partial/merge为4.43%/0.19%。16K初始窗的Prefill占64.13%、GEMM占30.70%，两个场景的热点顺序分别记录。FULL图以graph launch观察内部未展开的工作，保留opaque归因边界；partial/merge在eager Mixed窗口中可单独验证。

Mixed 的完整成本门包含一次 native metadata builder 和42层 bridge、partial、merge、Prefill全部启动；真实 B10/9q1、B64/63q1及长context B31/30q1的局部净降分别4.28%、14.15%、14.49%。GEMM的四个真实shape在固定配置下总净降9.37%，普通入口含主机包装的总净降8.19%。设备与主机总时间分别按实际窗口记录；这些局部测量覆盖指定算子成本，原wrapper结果对应完整双场景，吞吐与精度统一见[本文第 6 节](#6-精度与官方正式结果)。

CPU bounded嵌套计时还确认了真实index调用内部54次反射合104.369s；保留外层配对的17次调用中，嵌套反射占81.66%–90.31%。另11个cached长窗内部反射计时为0，CPU归因分别记录这些窗口与实际嵌套反射段。这一观察支持压缩默认内部配置库的反射范围，其他CPU成本保持独立计时边界。

```python
def _has_decode_workspace(query, metadata):
    sequences = metadata.seq_lens.numel()
    threshold = getattr(metadata, "seq_threshold_3D", None)
    if (type(threshold) is not int or sequences > threshold
            or getattr(metadata, "num_par_softmax_segments", None) != 16):
        return False
    for name, tail, strides in (
        ("softmax_segm_output", (16, 16, 128), (32768, 2048, 128, 1)),
        ("softmax_segm_max", (16, 16), (256, 16, 1)),
        ("softmax_segm_expsum", (16, 16), (256, 16, 1)),
    ):
        tensor = getattr(metadata, name, None)
        if (not isinstance(tensor, torch.Tensor) or tensor.ndim != len(tail) + 1
                or tensor.shape[0] < sequences or tensor.shape[1:] != tail
                or tensor.dtype != torch.float32 or tensor.device != query.device
                or tensor.stride() != strides):
            return False
    return True
```

页表、query前缀和序列长度必须同设备、整数dtype且具备规定维度与stride，容量检查不读取GPU内容。Prefill入口仅允许多查询、非FULL的既有兼容路径，未支持的捕获模式维持原实现。Decode工作区仍使用native metadata分配的三个FP32缓冲，检查其容量、16段以及精确shape/stride。任何一项不符合就返回False，不临时分配另一套workspace，也不改变调用方地址。

```python
def _can_split_mixed_q1(query, metadata, query_tile, cudagraph_mode):
    """Called only after the unchanged Prefill feature/layout compatibility gate."""
    return (query_tile == 16 and cudagraph_mode == CUDAGraphMode.NONE

class IluvatarPagedGQAMetadataBuilder(TritonAttentionMetadataBuilder):
    def build(self, common_prefix_len, common_attn_metadata, fast_build=False):
        metadata = super().build(common_prefix_len, common_attn_metadata, fast_build)
        metadata.iluvatar_mixed_has_q1 = False
        sequences = metadata.seq_lens.numel()
        if (self.vllm_config.speculative_config is None
                and select_query_tile(metadata.max_query_len,
                                      metadata.num_actual_tokens, sequences) == 16):
            starts_cpu = getattr(common_attn_metadata, "query_start_loc_cpu", None)
            if (isinstance(starts_cpu, torch.Tensor) and starts_cpu.device.type == "cpu"
                    and starts_cpu.ndim == 1 and starts_cpu.numel() >= sequences + 1
                    and starts_cpu.dtype in (torch.int32, torch.int64)):
                metadata.iluvatar_mixed_has_q1 = bool(
                    (starts_cpu[:sequences + 1].diff() == 1).any())
        return metadata
```

纯Decode仍要求最大query长度为1且关闭batch-invariant特殊模式。Mixed资格额外要求Q16、明确的eager NONE模式、builder已经确认存在q1及同一套合法工作区，FULL/其他模式不进入该分派。builder先调用native构造，再把标记初始化为False；只有非speculative且Q16几何成立时，读取已驻留CPU的query_start_loc_cpu并检查相邻差是否为1。该判断每个metadata build执行一次、42层共享，不触发seq_lens_cpu的lazy设备拷贝，也不按层扫描。

## 3. 宽输出 GEMM 的 program ID 分组

源文件为 [iluvatar ops/mm.py](../../FlagGems/src/flag_gems/runtime/backend/_iluvatar/ops/mm.py)。本节连续摘录四处相关代码，覆盖本阶段全部GEMM性能改动。原许可、导入、dtype提升、K循环、dot、store、边界mask及mm/mm_out接口保持原实现；调优配置、M/N/K key和FP32累积顺序也保持不变。改变的是同一网格中tile的访问次序及其保守资格，不改变矩阵乘法公式或输出所有权。

完整函数`_use_grouped_pid`，对应`mm.py`第50–61行：

```python
def _use_grouped_pid(args):
    """Conservative wide-output geometry; CPU scalars and dtype attributes only."""
    M, N, K = args["M"], args["N"], args["K"]
    BM, BN, GM = args["BLOCK_M"], args["BLOCK_N"], args["GROUP_M"]
    safe_offsets = all(math.ceil(value).bit_length() <= 31
                       for value in ((M * N) / (BM * BN), M * K, K * N, M * N))
    return (all(args[name].dtype == torch.bfloat16 for name in ("A", "B", "C"))
            and args["acc_dtype"] == tl.float32 and args["SPLIT_K"] == 1
            and safe_offsets and args["stride_am"] == K and args["stride_ak"] == 1
            and args["stride_bk"] == 1 and args["stride_bn"] == K
            and args["stride_cm"] == N and args["stride_cn"] == 1
            and N >= 2 * K and triton.cdiv(M, BM) >= GM and triton.cdiv(N, BN) > 1)
```

函数只读取M/N/K、BLOCK配置、张量dtype及stride这些CPU元数据。资格要求A/B/C均为BF16、FP32累积、SPLIT_K为1，以及dense A、转置视图B和dense C的精确布局。N至少为2*K、M方向tile数达到GROUP_M、N方向不止一个tile，且tile数量和全部线性offset满足31位范围时才启用分组。实际gate/up宽输出满足这些条件，QKV/O/down及其他不满足资格的调用保留原行优先映射。

完整`triton.heuristics`装饰器，连续摘录`mm.py`第76–91行：

```python
@triton.heuristics(
    {
        "EVEN_K": lambda args: args["K"] % (args["BLOCK_K"] * args["SPLIT_K"]) == 0,
        "UPGRADE": lambda args: math.ceil(
            (args["M"] * args["N"]) / (args["BLOCK_M"] * args["BLOCK_N"])
        ).bit_length()
        > 31,
        "UPGRADE_A_OFFS": lambda args: math.ceil(args["M"] * args["K"]).bit_length()
        > 31,
        "UPGRADE_B_OFFS": lambda args: math.ceil(args["K"] * args["N"]).bit_length()
        > 31,
        "UPGRADE_C_OFFS": lambda args: math.ceil(args["M"] * args["N"]).bit_length()
        > 31,
        "GROUPED": _use_grouped_pid,

)
```

既有EVEN_K和四类UPGRADE判断保留K尾部及宽地址处理逻辑。新增GROUPED由前面的资格函数计算，并由heuristics注入kernel的编译期参数。它沿用原libentry/libtuner链，不增加调优配置、修改M/N/K key或改变持久配置来源。普通入口计时包含这层CPU包装，设备单核时间与主机总时间分别记录。

```python
    @staticmethod
    def _sqlite_reflection_schema_safe(records) -> bool:
        for kind, name, ddl in records:
            if kind == "table":
                if (
                    not isinstance(ddl, str)
                    or not ddl
                    or "\0" in ddl
                    or not re.match(r"^\s*CREATE\s+TABLE\b", ddl, re.IGNORECASE)
                    or any(word in ddl.upper() for word in (
                        "REFERENCES", "FOREIGN", "VIRTUAL"
                    ))
                ):
                    return False
            elif kind == "index":
                if ddl is None:
                    if not name.startswith("sqlite_autoindex_"):
                        return False
                elif (
                    not isinstance(ddl, str)
                    or "\0" in ddl
                    or not re.match(
                        r"^\s*CREATE\s+(?:UNIQUE\s+)?INDEX\b", ddl, re.IGNORECASE
                    )
                ):
                    return False
            else:
                return False
        return True

```

全库schema门只接受普通CREATE TABLE与CREATE INDEX/CREATE UNIQUE INDEX，NULL索引DDL需为SQLite autoindex。table文本非空且无NUL、REFERENCES、FOREIGN或VIRTUAL，view、trigger及未知对象均回原路径。扫描覆盖全库所有table，因此同时约束目标表的出向FK和其他表到目标的入向FK。保守拒绝也覆盖SQL文本里出现这些字符串的情况，已有数据库语义由原prepare继续处理。

```python

                            )
```

